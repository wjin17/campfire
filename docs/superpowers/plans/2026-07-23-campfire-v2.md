# Campfire v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the app into Campfire — an always-on-top vocal-effects widget with tuner, browser+Windows song detection, synced lyrics, shell/payload auto-update from GitHub Releases, and a GitHub Pages download site.

**Architecture:** Spec at `docs/superpowers/specs/2026-07-23-campfire-v2-design.md` is the authority — every task implementer reads its relevant sections. Shell = `src/main` + `src/preload` + `resources/` (static). Payload = `src/renderer` (auto-updates).

**Tech stack:** as v1, plus `extract-zip` and `archiver` devDeps for payload/release tooling.

## Global Constraints

- All of v1's: TS everywhere (worklet JS exception), mic EC/NS/AGC false, latencyHint 'interactive', no comments unless non-obvious WHY, lint clean before commit.
- Names: package `campfire`, productName/executableName `Campfire`, appId `com.wjin17.campfire`. Repo github.com/wjin17/campfire.
- WS server binds 127.0.0.1 only. Payload zips verified by sha256 before activation. `SHELL_API_VERSION = 1` lives in `src/main/shell-api.ts`.
- E2E probes run with: `export LD_LIBRARY_PATH=$HOME/.cache/pw-syslibs/usr/lib/x86_64-linux-gnu:$HOME/.cache/pw-syslibs/usr/lib/x86_64-linux-gnu/nss:$LD_LIBRARY_PATH`
- Emscripten env for wasm rebuilds: `source ~/emsdk/emsdk_env.sh` then `native/autotalent/build.sh`.
- Tests: unit via `npm run test:unit`, DSP via `npm run test:dsp`, plus `.superpowers/probe-widget.mjs` e2e (created in Task 3).

Tasks are sequential; each ends with all suites green and one commit.

### Task 2: Shell services — tray, sizes, settings, WS server, SMTC helper

**Files:** Create `src/main/settings.ts`, `src/main/nowplaying-server.ts`, `src/main/tray.ts`, `resources/smtc-poll.ps1`, `tests/unit/nowplaying-schema.test.ts`; Modify `src/main/index.ts`, `src/preload/index.ts`, `src/preload/index.d.ts`.

- `settings.ts`: `loadSettings()/saveSettings(partial)` JSON at `app.getPath('userData')/settings.json`; shape `{ x?, y?, expanded: boolean, micGain: number, reverbMix: number, autotune: {enabled, root, mode, strength}, lyricsLeadMs: number (default 250), wsPort?: number }`. Window restores x/y+expanded on boot, saves on move/close.
- Window sizes: small 320×96, expanded 400×560. `setExpanded(bool)` IPC resizes (keep top-left anchored).
- `nowplaying-server.ts`: WebSocket server (use `ws` dep — add it) on 127.0.0.1:17640, fallback 17641 (persist chosen port). Export pure `parseNowPlaying(raw: string): NowPlaying | null` validating the spec schema (source/title/position/duration/playing/ts types; reject others) — unit-test it (valid msg, wrong types, junk JSON, extra fields ok). Valid messages → `win.webContents.send('now-playing', msg)`.
- `smtc-poll.ps1` per spec: WinRT GSMTC poll 500 ms, one JSON line per tick `{source:'smtc',title,artist,position,duration,playing,ts}` on stdout. Main spawns it only when `process.platform === 'win32'` (`spawn('powershell.exe', ['-NoProfile','-ExecutionPolicy','Bypass','-File', ...])`), parses lines through the same `parseNowPlaying`, respawns on exit with backoff (max 3). Not testable in WSL beyond syntax — mark for Windows manual check.
- `tray.ts`: tray icon (use `resources/icon.png`), menu Show/Hide, Mic On/Off (sends 'tray-mic-toggle' to renderer; renderer reports state back via `setMicActive` to update the label), Quit.
- Preload additions: `onNowPlaying(cb)`, `setExpanded(bool)`, `minimizeToTray()`, `setMicActive(bool)`, `onTrayMicToggle(cb)`, `getSettings()`, `saveSettings(partial)`, `payloadVersion()` (stub returning app version until Task 5).

Steps: implement → suites green (new unit test included) → commit `feat: shell services — tray, settings, now-playing ingest`.

**Produces:** the full preload API of the spec; `NowPlaying` type exported from `src/renderer/src/types/nowplaying.d.ts` (shared shape, duplicated type is fine).

### Task 4: Tuner

**Files:** Modify `native/autotalent/wrapper.c` (+rebuild wasm), `src/renderer/public/worklet/autotalent-processor.js`, `src/renderer/src/audio/autotune/portmap.ts` (+`detectedPitch: number; confidence: number` port indices — ports 27/28 are control OUTPUTS so `at_port_is_control_input` is false for them; match by name substring "detected pitch"/"confidence" over all control ports), `src/renderer/src/audio/engine.ts`, `src/renderer/src/audio/autotune/autotune-node.ts`, App.tsx; Create `src/renderer/src/audio/tuner.ts`, `src/renderer/src/components/Tuner.tsx`, `tests/unit/tuner.test.ts`; Modify `tests/unit/wasm.test.ts` or portmap test for the new exports; extend `src/renderer/src/harness.ts` + `tests/dsp/tuner.spec.ts`.

- wrapper.c: `float at_get_control(unsigned long p) { return controls[p]; }` (output ports are already connected to controls[]). Rebuild wasm, commit binary.
- Worklet: every 128-sample block count frames; every ~10 blocks (≈30 ms… use every 5th block ≈15 ms at 44.1k → too chatty; every 10 blocks ≈29 ms ok) post `{type:'pitch', semitones, confidence}` read via at_get_control using two port indices passed in processorOptions.
- Always-in-chain: `enableAutotune` semantics change — `createAutotuneNode` happens at `start()` (mic on) and node sits `source→worklet→micGain` permanently; toggle ON = set amount=strength, Mix=1; toggle OFF = amount=0, Mix=0 (dry through plugin — verify DSP bypass test: with amount/mix 0 a 449 Hz tone must emerge ≈449, add to tuner.spec.ts). Remove connect/disconnect juggling and the race guard (no longer needed); keep wasm-load-failure → autotune+tuner disabled, effects otherwise fine.
- `tuner.ts` pure helpers (unit-tested): `semitonesToNote(st: number): {note: string; cents: number}` (st is w.r.t. A440; e.g. 0→A+0¢, 0.196→A+20¢ (449 Hz≈+35¢? compute exactly: 449/440 = 35.1¢ → st 0.351 → A +35¢), 3.5→ C +50 or Db −50 boundary: round-half-up to nearest note, cents in [−50,50)).
- `Tuner.tsx`: note name + needle bar; dimmed under confidence threshold (pick by observing fake-mic silence vs tone; expose constant).
- DSP test: harness renders 449 Hz sine through node with correction off, collects posted pitch messages, asserts median reported pitch ≈ +0.35 st (±0.1) and output freq ≈449 (bypass transparent).

Steps: implement (wasm rebuild first) → suites green incl. new DSP spec → commit `feat: tuner from autotalent pitch detection, worklet always in chain`.

**Produces:** `engine.onPitch(cb: (p: {semitones, confidence}) => void)`; autotune toggle no longer inserts/removes the node.

### Task 6: Lyrics stack

**Files:** Create `src/renderer/src/lyrics/{clean.ts,lrc.ts,lrclib.ts,sync.ts}`, `src/renderer/src/components/Lyrics.tsx`, `tests/unit/{clean,lrc,sync,lrclib-match}.test.ts`; Modify App.tsx.

- `clean.ts`: `cleanTitle(raw): {title, artist?}` — strip `(...)`/`[...]` groups containing official|video|audio|lyric|lyrics|karaoke|hd|4k|remaster|mv|visualizer (case-insens), strip `feat.|ft.` clauses, strip trailing `- YouTube`, split on first ` - ` into artist/title when present. Unit-test ≥8 real-world cases incl. `Artist - Song (Official Video) [4K]`, `Song (Lyrics) ft. X`, no-artist plain title.
- `lrc.ts`: `parseLrc(text): {t:number; text:string}[]` sorted; handles multiple timestamps per line `[01:10.00][02:20.00]words`, ignores metadata tags. Unit tests.
- `lrclib.ts`: `searchLyrics(title, artist, duration?)` → GET `https://lrclib.net/api/search?track_name=&artist_name=` (fallback `?q=`), score results: normalized-string similarity of title+artist (export `matchScore(a,b)` pure, unit-tested) + duration proximity bonus (±5 s); return best `syncedLyrics` or null. In-memory cache keyed by title|artist.
- `sync.ts`: class `LyricsClock`: `update(msg: NowPlaying)` stores position/ts/playing; `now(leadMs): number` returns `position + (playing ? (Date.now()-ts)/1000 : 0) + leadMs/1000`; source arbitration: prefer extension, smtc only if no extension msg within 5 s. `currentLineIndex(lines, t)` binary search. All pure parts unit-tested (fake timestamps — inject `nowFn` for testability, no real Date.now in tests).
- `Lyrics.tsx`: subscribes `api.onNowPlaying`; on track change (title changed) → cleanTitle → searchLyrics → lines; rAF-driven (throttled 4 Hz) prev/current/next render, current highlighted pink; states: "nothing playing", "no synced lyrics — <title>", lines. Lead slider (from Task 3) feeds `now()`.

Steps: implement → suites + probe green → commit `feat: lyrics lookup and sync`.

**Produces:** `LyricsClock`, wired lyrics panel.
